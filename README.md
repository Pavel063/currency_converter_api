# Конвертор валют на Python + Flask

Учебное веб-приложение для конвертации валют. Курсы не зашиты в коде: приложение получает их через **Frankfurter API**, используя источник **European Central Bank (ECB)**.

## Возможности

- получение актуального опубликованного курса через внешний API;
- конвертация нескольких валют;
- отображение даты курса и источника;
- сохранение истории операций в SQLite;
- демонстрационные endpoints с тремя намеренно созданными уязвимостями.

## Запуск в PyCharm

1. Открыть папку проекта.
2. Создать Virtualenv с Python 3.11+.
3. В Terminal выполнить:

```bash
pip install -r requirements.txt
```

4. Запустить `app.py`.
5. Открыть `http://127.0.0.1:5000`.

Для работы с внешним API требуется подключение к интернету.

## Источник курсов

Используется Frankfurter API v2. В приложении запросы направляются на endpoint ECB provider:

`https://api.frankfurter.dev/v2/providers/ecb/rate/<base>/<quote>`

Frankfurter предоставляет данные от официальных источников, включая ECB, и не требует API-ключа. ECB публикует справочные курсы обычно около 16:00 CET в рабочие дни.

## Три учебные уязвимости

### 1. SQL Injection — CWE-89

Endpoint: `/vulnerable/search`

Причина: пользовательский параметр `user` напрямую конкатенируется со строкой SQL.

Для исправления необходимо использовать параметризованные SQL-запросы, как это уже сделано в безопасных частях приложения.

### 2. Reflected XSS — CWE-79

Endpoint: `/vulnerable/greet`

Причина: параметр `name` возвращается в HTML без экранирования.

Для исправления следует использовать безопасный шаблонизатор и контекстное экранирование.

### 3. IDOR / Broken Access Control — CWE-639

Endpoint: `/vulnerable/history/<id>`

Причина: сервер возвращает запись только по переданному ID и не проверяет, имеет ли текущий пользователь право на её просмотр.

Для исправления необходимо добавить аутентификацию и авторизацию на уровне каждой записи.

## Важно

Уязвимые endpoints добавлены специально для учебного тестирования локального приложения. Основной endpoint `/convert` использует параметризованный SQL-запрос для записи истории и не принимает курс от пользователя.
